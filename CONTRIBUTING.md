# Contributing to MOSE

Thanks for your interest in MOSE. This page is the short version: branch,
work, open a pull request. The [Developer Guide][devguide] has the detail —
coding conventions, architecture, and how to extend the solver.

## Workflow

Every change reaches `main` through a pull request. Direct pushes to `main`
are blocked, including for maintainers.

```bash
# 1. Clone with submodules (MOSE will not build without them)
git clone --recurse-submodules https://github.com/open-hydra/MOSE.git
cd MOSE

# 2. Branch from main
git switch main && git pull
git switch -c feature/my-change

# 3. Build
./install.sh build --compilers=gnu --use-openmp
./install.sh compile          # iterative rebuilds after the first build

# 4. Work, in small focused commits
git commit -m "Add SLAU2 Riemann solver"

# 5. Push and open a pull request against main
git push -u origin feature/my-change
```

If you have write access, branch directly in this repository rather than
working from a fork: some automation does not run on forks (see
[AUTHORS.md is generated](#authorsmd-is-generated) below).

## Before you open the pull request

Run the fast tests locally:

```bash
ctest --test-dir build -L fast --output-on-failure
```

Better, enable the pre-push hook once and let it run that tier for you on
every `git push`:

```bash
git config core.hooksPath .githooks
```

It is skipped automatically if you have no `build/` directory yet.

CI runs the wider suite on every pull request, excluding cases that need
optional dependencies:

```bash
ctest --test-dir build --output-on-failure --timeout 300 \
  --label-exclude "needs-cantera|needs-sundials|needs-mpi"
```

See [Testing][testing] for the label tiering, and `test/TESTING-PLAN.md`
for what belongs in each tier.

### Checklist

- [ ] Compiles with `-std=f2008 -Wall -Wextra` without new warnings
- [ ] No line exceeds 132 characters
- [ ] New subroutines declare `implicit none` and argument intents
- [ ] `ctest -L fast` passes
- [ ] New functionality has at least one test case
- [ ] Documentation updated if user-facing behaviour changed
- [ ] Commit messages use imperative mood ("Add ...", not "Added ...")

## AUTHORS.md is generated

**Do not edit `AUTHORS.md` by hand.** It is generated by
`scripts/generate-authors.py` from git history, and any manual edit is
overwritten.

You do not need to add yourself. When you push a branch, CI regenerates the
file and commits it onto that branch, so your name arrives with your first
merged pull request. A `chore: update AUTHORS.md` commit appearing on your
branch is that automation, not a mistake.

Two cases do need a human:

- **You commit under more than one name or address.** Add a `.mailmap` entry
  folding your identities together, otherwise you appear twice. Verify with
  `git check-mailmap "Your Name <your@email>"`.
- **Curated sections.** `original_authors`, `present_maintainers` and
  `alumni` live in `scripts/contributors.yml` and are maintained by hand.

Release credit is recorded separately in `CITATION.cff`, which maintainers
update at tag time.

## Reporting bugs

Open an issue with the MOSE version or commit hash, compiler and version,
build flags, the input file, and the smallest case that reproduces the
problem.
